# Career Repository Governance

This repository is the persistent source of truth for Fares Mohamed's career materials, job applications, and professional positioning.

## Source-of-truth order

When facts conflict, use this order:

1. `CAREER_PROFILE.md` for verified career facts and capabilities.
2. Current authoritative project repositories for project-specific facts, implementation details, metrics, and recent milestones.
3. Resume LaTeX sources under `latex/`.
4. Generated/public resume PDFs.
5. `APPLICATIONS.md` for application history and status.
6. `LINKEDIN.md` for LinkedIn strategy and content history.
7. Chat/project context and memory only as leads to verify, never as authority when repository evidence exists.

A PDF is an output, not the master career database.

## Mandatory startup for career work

Before job hunting, tailoring a resume, preparing an application, or creating career-focused LinkedIn content:

1. Read `AGENTS.md`.
2. Read `CAREER_PROFILE.md`.
3. Read `APPLICATIONS.md` when applications or job discovery are involved.
4. Read `LINKEDIN.md` when LinkedIn content or positioning is involved.
5. Read the relevant LaTeX resume source when selecting or modifying a resume.
6. Inspect authoritative project repositories when newer project facts could materially affect the task.

Do not ask Fares to repeat information already available from these sources.

## Updating the career record

Keep `CAREER_PROFILE.md` current as meaningful work happens. A development belongs there when it materially changes demonstrated capability, responsibility, achievement, measurable result, or professional positioning.

Do not add every commit, dependency, experiment, or technology mentioned in a repository. Do not infer proficiency merely because a technology appears in source code or configuration.

Before adding a claim, verify it from an authoritative source. Never invent or inflate experience, dates, metrics, skills, qualifications, certifications, work authorization, compensation, or achievements.

When a project repository contains newer verified information than `CAREER_PROFILE.md`, update the profile before relying on the new information in an application or public post.

## Resume maintenance

Resumes are role-specific projections of `CAREER_PROFILE.md`, not independent factual sources.

- Keep published resumes concise and application-ready.
- Tailor emphasis for the role without changing underlying facts.
- Prefer modifying LaTeX sources and regenerating PDFs together.
- Do not silently let a PDF and its source diverge.
- Add a new resume variant only when a genuinely different target warrants one.

## Job applications

Use `APPLICATIONS.md` to prevent duplicate applications and preserve continuity across sessions. Record serious applications and meaningful status changes.

General workflow:

Discover -> Verify -> Evaluate -> Prioritize -> Research -> Tailor -> Apply/Assist -> Track -> Follow Up

Never fabricate an answer to pass screening. Ask Fares when a consequential application question cannot be resolved from authoritative sources.

## LinkedIn

Use `LINKEDIN.md` to preserve positioning, publishing conventions, and notable content history. LinkedIn should reinforce the same evidence-based professional profile used for job hunting.

Discussion or drafting is not permission to publish. Publish or schedule only when Fares explicitly asks.

## Repository writes

When career facts, application state, or LinkedIn strategy materially change during a ChatGPT Project session, update this repository so the next session can recover the state from GitHub rather than depending on chat memory.

Keep changes focused, factual, and auditable through Git history.
